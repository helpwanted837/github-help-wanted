# 07 - 内容撰写规范

> github-help-wanted.com 文案撰写标准化指南

---

## 1. 基本要求

### 字数标准

| 页面类型 | 最低字数 | 建议字数 |
|----------|----------|----------|
| **Pillar** | 3000 | 3500-4000 |
| **Cluster** | 2000 | 2000-2500 |
| **扩展** | 1500 | 1500-2000 |
| **信任页** | 800 | 1000 |

### 核心原则

1. **权威引用优先** - 每篇至少 5 条权威来源引用
2. **不写内链** - 智能内链系统自动处理
3. **Schema 富文本** - 必须包含结构化数据元素
4. **E-E-A-T 导向** - 体现专业性、权威性、可信度

## 2. 权威引用规范

### 必须包含 5+ 条引用

**引用来源优先级**：

| 优先级 | 来源类型 | 示例 |
|--------|----------|------|
| ⭐⭐⭐ | 官方文档 | GitHub Docs, MDN, AWS Docs |
| ⭐⭐⭐ | 学术/研究机构 | Stanford, MIT, IEEE |
| ⭐⭐⭐ | 行业报告 | Stack Overflow Survey, Gartner, Forrester |
| ⭐⭐ | 权威媒体 | TechCrunch, Wired, The Verge |
| ⭐⭐ | 知名博客 | Martin Fowler, Kent Beck, Joel on Software |
| ⭐ | 工具官方博客 | Atlassian Blog, JetBrains Blog |

### 引用格式

**Markdown 引用块格式**：

```markdown
> "DevOps is not a goal, but a never-ending process of continual improvement."
> — Jez Humble, Co-author of "Continuous Delivery"
```

**正文内引用格式**：

```markdown
According to the [2024 Stack Overflow Developer Survey](https://survey.stackoverflow.co/2024/),
over 70% of professional developers use Git for version control.
```

**参考文献区块**（文末必须包含）：

```markdown
## References

1. [GitHub Docs: About open source](https://docs.github.com/en/get-started/exploring-projects-on-github/finding-ways-to-contribute-to-open-source-on-github) - Official GitHub documentation

3. [The State of DevOps Report 2024](https://dora.dev/research/) - DORA research

5. [Martin Fowler: Continuous Integration](https://martinfowler.com/articles/continuousIntegration.html) - Expert perspective
```

## 6. SEO 写作规范

### 标题优化

- **H1**: 只有一个，包含主关键词
- **H2**: 3-8 个，每个包含长尾关键词
- **H3**: 细分 H2 内容，自然使用关键词

### 关键词密度

- 主关键词：1-2%（每 100 字出现 1-2 次）
- 长尾关键词：自然分布在 H2/H3 和正文中

### Meta 优化

```
Title: [Primary Keyword]: [Value Proposition] [Year]
       ← 60 chars max →

Description: [Hook] + [What you'll learn] + [Call to action]
             ← 150-160 chars →
```

**示例**：
```
Title: DevOps Engineer Salary 2025: Complete Guide & Data
Description: Discover 2025 DevOps engineer salaries by location and experience. Includes negotiation tips and career growth strategies.
```

## 7. 写作风格指南

### 语气和风格

- **专业但易懂** - 避免过度术语，必要时解释
- **直接** - 开门见山，不绕弯子
- **实用** - 提供可操作的建议
- **数据驱动** - 用数据支持观点

### 禁止事项

| ❌ 禁止 | ✅ 替代方案 |
|--------|------------|
| 空洞的形容词（"amazing", "incredible"） | 具体数据（"reduced by 40%"） |
| 过度推销语气 | 客观分析利弊 |
| 未经证实的声明 | 引用权威来源 |
| 复杂长句 | 短句 + 清晰结构 |
| 被动语态 | 主动语态 |
| 第一人称（"I think"） | 客观陈述 |

### 段落规范

- 每段 2-4 句
- 每段一个主题
- 使用过渡词连接段落

```

│   ├── salary/
```

### 命名规则

- 全小写
- 用连字符 `-` 分隔单词

- 避免特殊字符

## 10. 发布流程

### Step 1: 撰写
文案按模板撰写，确保满足所有规范

### Step 2: 提交
将 `.md` 文件放入正确目录，`draft: true`

### Step 3: 审核
架构师检查质量、SEO、Schema

### Step 4: 排期
设置 `date` 为目标发布时间（未来日期）

### Step 5: 发布
将 `draft: true` 改为 `draft: false`，提交

### Step 6: 自动构建
GitHub Actions 每小时检查，到期自动发布
