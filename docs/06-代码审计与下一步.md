  ssh-keygen -t ed25519 -f ~/.ssh/id_ghw -C "ghw@example.com"

  Host github-ghw
    HostName github.com
    User git
    IdentityFile ~/.ssh/id_ghw

### 阶段 2：内容填充策略

#### 2.1 内容填充优先级

```
Day 1: 信任页面补充 + 6个 Pillar 页

Day 4-5: P1 长尾词（50 页）

```

#### 2.2 Pillar 页填充（必须优先）

| Section | URL | 字数要求 | 内容要点 |
|---------|-----|----------|----------|
| Open Source | `/open-source/` | 3000+ | 开源贡献入门、为何参与、如何找项目 |
| GitHub Pages | `/github-pages/` | 3000+ | 什么是 GitHub Pages、优势、快速上手 |
| DevOps Engineer | `/devops-engineer/` | 3000+ | 什么是 DevOps、职业路径、技能要求 |
| SDLC | `/sdlc/` | 3000+ | 软件开发生命周期、各阶段、方法论 |
| Unit Testing | `/unit-testing/` | 3000+ | 什么是单元测试、为何重要、基本原则 |
| Product Management | `/product-management/` | 3000+ | PM 角色、职责、框架、工具 |

**要求**：
- 每个 Pillar 页内链到所有 Cluster 页
- 内容详尽，覆盖该主题的核心概念
- 包含 FAQ Section（触发 FAQPage Schema）

#### 2.3 Cluster 页内容模板

当前占位页结构：
```markdown
## Quick Answer
## Step-by-Step
## Common Mistakes
## FAQs
```

**填充要求**：
- 1500+ 字
- Quick Answer：直接回答关键词问题（Featured Snippet 优化）
- Step-by-Step：可操作的步骤
- Common Mistakes：避坑指南
- FAQs：3-5 个常见问题

#### 2.4 发布时间设置

```bash
# 生成 P0 页面（已完成，但 draft: true）
# 要发布时，编辑 frontmatter：
# - draft: false
# - date: 未来时间（带时区）

# 示例：设置 3 天后 10:23 发布
date: 2025-12-26T10:23:45+08:00
```

**注意**：
- 时分秒随机化，避免固定时间点
- 不同 Category 错开发布
